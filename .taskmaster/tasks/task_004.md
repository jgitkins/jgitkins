## Subtasks

### 4.4. [infra] 이 프로젝트용 하네스 엔지니어링 기반 구성

**Status:** pending  
**Dependencies:** None  

Codex 같은 에이전트가 이 리포지터리에서 안정적으로 작업할 수 있도록 문서, 실행 환경, 검증 루프, 관측 가능성, 작업 규약을 정비한다.

**Details:**

[source: https://openai.com/ko-KR/index/harness-engineering/]
이 작업의 하네스 엔지니어링은 특정 CI/CD 제품 도입이 아니라, 에이전트가 읽기 쉽고 실행 가능하며 반복 검증 가능한 엔지니어링 환경을 만드는 것이다. 검토 및 구현 범위는 다음을 포함한다. 1) AGENTS.md 를 짧은 목차형 진입점으로 유지하고, 실제 신뢰 가능한 지식은 docs/ 하위에 구조화하여 기록 시스템으로 정리한다. 2) server/web/runner 각 모듈의 실행 방법, 테스트 방법, 주요 아키텍처 제약, 코드 수정 규칙을 에이전트가 탐색하기 쉬운 문서와 스크립트로 정비한다. 3) 변경 단위별로 재현 가능한 검증 루프를 만들기 위해 로컬 실행, 테스트, 로그 확인, 필요 시 브라우저 기반 확인 절차를 표준화한다. 4) 에이전트가 애플리케이션 상태를 읽고 문제를 추론할 수 있도록 로그, 메트릭, 트레이스 또는 그에 준하는 관측 신호 노출 방식을 정리한다. 5) 큰 작업을 더 작은 실행 단위로 분해하고, 계획 문서와 작업 기록이 드리프트하지 않도록 운영 규약을 수립한다. 산출물은 리포지터리 작업 하네스 개선안, 필요한 문서/스크립트/체크리스트 목록, 그리고 후속 구현 backlog 다.

**Test Strategy:**

문서 진입점에서 실제 실행/검증/관측 절차까지 에이전트가 추가 질문 없이 따라갈 수 있는지 점검하고, 대표 작업 1~2개를 기준으로 문서와 스크립트만으로 재현 가능한 피드백 루프가 형성되는지 검증한다.
